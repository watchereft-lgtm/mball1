# 🔮 Магический шар предсказаний

> **В репозиторий нужны отдельные файлы, а не архив.** Если положить сюда `.zip`, Streamlit
> ответит `Error: Streamlit requires raw Python (.py) files, not .zip` — он не умеет запускать код
> из архива. Загружайте файлы из этой папки по отдельности: `app.py`, `pools.json`,
> `requirements.txt` и папки `.streamlit` и `.github`.

Веб-приложение на Streamlit: на экране компьютера висит **большой QR-код**, телефон по нему
открывает **игру**, игрок задаёт вопрос — свой или готовый из списка — и получает предсказание шара.

![Пример QR-кода, который показывает витрина](docs/qr-example.png)

Один процесс, один порт, две роли:

| Адрес | Что показывает |
| --- | --- |
| `http://<ваш IP>:8501/` | витрина: название и QR-код для аудитории |
| `http://<ваш IP>:8501/?screen=game` | игра, которую открывает телефон (эта ссылка зашита в QR) |

Ничего не сохраняется: ни файлов, ни базы, ни аккаунтов. История живёт только во вкладке браузера.
Всё работает в локальной сети и **без интернета** — после того как зависимости скачаны.

## Как это выглядит

- **Витрина.** Тёмный экран с названием и QR-кодом во всю ширину. Ничего больше: ни адреса, ни
  инструкций — аудитория просто наводит камеру.
- **Игра на телефоне.** Поле вопроса, рядом список готовых школьных вопросов («Сдам ли я
  контрольную?», «Позовут ли меня гулять?»), кнопка и крупный ответ шара под ней.

## Деплой на Streamlit Community Cloud

Приложение не требует настройки под хостинг: ссылку для QR оно берёт из адреса, по которому его
открыли (`st.context.url`), поэтому в коде нет ни одного зашитого адреса.

1. Залейте репозиторий на GitHub (файлы из этой папки).
2. Откройте [share.streamlit.io](https://share.streamlit.io) → **New app** → выберите репозиторий.
3. **Main file path**: `app.py`. Больше ничего указывать не нужно.
4. Зависимости Streamlit поставит из `requirements.txt`, тему возьмёт из `.streamlit/config.toml`.

Главное — чтобы `app.py`, `pools.json`, `requirements.txt` и `.streamlit/config.toml` лежали в
корне репозитория. Получится адрес вида `https://имя-приложения.streamlit.app`, и витрина на нём
сама покажет QR-код со ссылкой `https://имя-приложения.streamlit.app/?screen=game`.

Нужен свой домен — задайте адрес явно, одним из двух способов:

```
переменная окружения MAGIC_BALL_PUBLIC_URL = https://ball.example.org
или открыть витрину с параметром          ?url=https://ball.example.org
```

Тогда и QR, и подпись на витрине будут вести на этот адрес. Параметр `?url=` удобен, чтобы
проверить адрес, не трогая настройки приложения.

## Локальная разработка (Windows)

Локальный запуск нужен только для отладки; в облаке он не используется.

```powershell
.\setup.ps1      # один раз: скачает зависимости в .pylibs (~250 МБ)
.\run.ps1        # запустит сервер и напечатает ссылку
```

Нужен запуск в фоне, без окна консоли, с логом на диске:

```powershell
.\start-detached.ps1    # лог в server.log, номер процесса в server.pid
.\stop-detached.ps1     # остановить
```

`setup.ps1` скачивает колёса с PyPI **без pip** и распаковывает их в `.pylibs` рядом с `app.py`.
Так сделано намеренно: pip в средах с ограниченными правами не может писать в свои временные
папки, а `setup_deps.py` обходится только стандартной библиотекой. Глобально не устанавливается
ничего, системный Python тоже не трогается. В облаке этот путь не нужен — там работает
`requirements.txt`.

Первый запуск `setup.ps1` занимает несколько минут и качает около 250 МБ (в основном pandas,
numpy и pyarrow, которые тянет Streamlit). Нужен только питоновский `packaging` — он есть в любом
интерпретаторе с pip. Скрипт сам подбирает версии: если свежий релиз пакета не собирается под вашу
систему (так случилось с `watchdog 6` на Windows), он откатывается на предыдущий и пишет об этом.
Битая установка лечится так:

```powershell
.\setup.ps1 -Clean
```

Если PowerShell запрещает скрипты, есть `start.cmd` — просто двойной клик, он сам обходит
политику выполнения.

Linux и macOS:

```bash
./setup.sh
./run.sh              # или ./run.sh --port 8600
```

Полезные параметры запуска:

```powershell
.\run.ps1 -Port 8600        # другой порт, если 8501 занят
.\run.ps1 -Ip 192.168.0.10  # если автоматически определился не тот адрес
```

## Локальная сеть: телефон в той же сети

Этот раздел нужен, только если вы запускаете приложение у себя, а не в облаке. Адрес вида
`192.168.x.x` не маршрутизируется из мобильного интернета: телефон должен быть подключён к тому
же Wi-Fi, что и компьютер, а мобильный интернет на нём лучше выключить.

**Если компьютер раздаёт Wi-Fi с телефона** (адрес `192.168.43.x`), раздача должна быть включена
постоянно, пока идёт игра. Стоит ей выключиться — Windows снимет адрес, адаптер уйдёт в
`169.254.x.x`, и телефон перестанет открывать страницу: сервер работает, но сети, по которой он
был доступен, больше нет. Признак: в ссылке, которую напечатал `run.ps1`, оказался адрес вроде
`10.x.x.x` вместо `192.168.43.x`. Запустите `run.ps1` заново после восстановления раздачи.

**Брандмауэр Windows** — единственный шаг, который нельзя пропустить. Один раз, от администратора:

```powershell
cd magic-ball
.\allow-firewall.ps1
```

Скрипт открывает порт только для вашей подсети и требует «Частный» профиль сети. Удалить правило:
`.\allow-firewall.ps1 -Remove`. Если Windows не даст определить подсеть, порт откроется для всех
адресов — скрипт скажет об этом прямо.

В облаке ни брандмауэр, ни локальный адрес не нужны: телефоны заходят по публичной ссылке.

## Наполнение: пулы предсказаний

Все фразы лежат в `pools.json` и правятся в блокноте, без Python.

```json
"my_pool": { "title": "Мой набор", "enabled": true, "category": "later",
             "phrases": ["Первая фраза", "Вторая фраза"] }
```

- ключ (`my_pool`) — любой латиницей, больше нигде не нужен;
- `title` — как набор называется в приложении;
- `enabled` — `true` набор играет, `false` выключен;
- `category` — одна из `yes`, `no`, `later`, `vague`;
- `phrases` — список фраз.

Как выбирается ответ: сначала случайно тянется **категория** среди включённых наборов, затем фраза
внутри неё. Поэтому подряд не выпадает пять «да». Фраза не повторяется, если она входила в
последние три ответа. Если выключить все наборы, игра молча включает `classic` — пустого шара не
бывает.

Наборы «из коробки»: `classic*` (классические ответы шара), `school*` (учёба, контрольные, друзья,
перемены), `tease` (подколы), `scary` (страшилки, **выключены**), `motivation` (мотивация,
выключена). Итого 11 наборов и около 150 фраз: да — 65, нет — 30, позже — 20, туманно — 35.

## Что в репозитории

| Файл | Зачем |
| --- | --- |
| `app.py` | всё приложение: витрина и игра |
| `pools.json` | фразы и выключатели наборов |
| `requirements.txt` | зависимости для облака (Streamlit ставит их сам) |
| `.streamlit/config.toml` | тема и оформление, работают и в облаке, и локально |
| `setup_deps.py` | загрузка зависимостей без pip — только для локального запуска |
| `setup.ps1` / `setup.sh` | обёртки установки для Windows и Unix |
| `run.ps1` / `run.sh` | локальный запуск: адрес, порт, ссылка, Streamlit |
| `start.cmd` | локальный запуск в один двойной клик на Windows |
| `start-detached.ps1` / `stop-detached.ps1` | запуск и остановка сервера отдельным процессом, лог в `server.log` |
| `allow-firewall.ps1` | правило брандмауэра для локальной сети (нужен админ) |
| `test_app.py`, `verify.ps1`, `probe_url.py` | самопроверка без браузера |
| `.github/workflows/checks.yml` | те же проверки в CI на каждый push |
| `docs/qr-example.png` | пример QR-кода для этого README |

`.pylibs/`, `.wheels/`, `.port`, `.ip`, `server.log` и `.testtmp/` в репозиторий не попадают — они
в `.gitignore`.

## Проверки

```powershell
.\verify.ps1
```

28 проверок: обе страницы запускаются без исключений, QR рисуется картинкой, поле вопроса и список
готовых вопросов на месте, выбор из списка подставляется в поле, кнопка выдаёт предсказание,
счётчик растёт, одна и та же фраза не выпадает дважды подряд, «страшилки» по умолчанию выключены.
Отдельная группа проверяет сборку ссылки для QR: из облачного адреса, из `localhost`, из локальной
сети и через `MAGIC_BALL_PUBLIC_URL`.

Если сервер уже запущен, `verify.ps1` дополнительно прогоняет `probe_url.py`: он подключается к
живому серверу по WebSocket и присылает адрес так, как это делает браузер, — так проверяется, что
QR действительно берёт адрес из запроса. Содержимое QR-картинки сверялось по пикселям с эталонным
QR — совпадение точное.

CI гоняет проверки на `windows-latest` при каждом push, причём зависимости ставит **из
`requirements.txt` через pip** — то есть ровно так, как это сделает Streamlit Cloud.

## Если телефон не открывает игру

1. Телефон и компьютер в одной сети, мобильный интернет на телефоне выключен?
2. Телефон показывает `http://127.0.0.1:...` — значит в QR попал неверный адрес: запустите
   `.\run.ps1 -Ip <ваш IPv4>` явно.
3. Страница бесконечно грузится — почти всегда брандмауэр: выполните `.\allow-firewall.ps1`.
4. Быстрая проверка сети с телефона: откройте `http://<ваш IP>:8501/_stcore/health`. Должно
   появиться слово `ok`. Если да, а страница не грузится — дело в браузере (инкогнито, кеш,
   подождать 20–30 секунд на первой загрузке). Если тайм-аут — сеть не пропускает: телефон,
   раздающий Wi-Fi, часто изолирует клиентов друг от друга, тогда нужен обычный роутер.
5. Остановили `run.ps1` — ссылка в телефоне перестанет работать, это нормально.

## Технологии

Python 3.10+, Streamlit 1.65, qrcode 8.2, Pillow. Никаких внешних сервисов: QR генерируется
локально, страница отдаётся локально, данные никуда не уходят.
